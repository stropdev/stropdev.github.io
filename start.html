Start

First ten minutes

This goes once through what you do all day: open a project, find a file, change it, search and replace across files, and commit. If you know Vim, the editing is already in your hands and the rest is a handful of Space keys.

1. Install

curl -fsSL https://strop.dev/install.sh | sh
strop --version

The build is for Linux and WSL on x86_64. It is one file; nothing else needs installing and there is no configuration to write.

2. Open a project

cd ~/src/myproject
strop

The directory you start in is the project. The finder, search and new terminals all work from there, whichever file you are in. strop src/main.rs opens a file straight away, and strop src/main.rs:120 opens it at a line.

Space ? lists every key, and :q quits, as you would expect.

3. Find a file

Press Space f and type part of the name. A match in the file name beats a match in a directory name, and several words must all match, so core.c sched finds kernel/sched/core.c. Enter opens the selected file.

With nothing typed the list starts with your other open files, then the files you open most in this project. Space b lists open buffers, and Ctrl-^ flips to the previous one.

4. Edit

Edit as you do in Vim: operators, motions, text objects, counts, registers, macros, Visual mode, . to repeat, u and Ctrl-R to undo and redo, :w to save. A plain yank also goes to the system clipboard.

If a key does something other than what Neovim does, that is a bug, unless it is on the short list in Coming from Neovim.

5. Search the project

Space / opens search. Results appear as you type, grouped by file, with a preview of the selected hit. Search is smart-case: lowercase matches either case, and one capital letter makes case count. Alt-R switches to a regular expression, Alt-W to whole words, Alt-C to exact case.

Enter opens the hit. Space / again brings the same search back, so you can work through the list.

6. Replace across files

Space R opens the same search with a second field. Type what to find, press Tab, type what to put there. Every hit is shown as a - line and a + line while you type.

  • Ctrl-X leaves one hit out; Ctrl-D leaves a whole file out.
  • Enter shows the full diff for review. Enter again changes the files and writes them.
  • u in the review puts everything back, on disk as well.

7. Edit the hits by hand

When a replace is not enough, press Ctrl-O in the search results. The hits open as one buffer, each with a few lines around it. Edit them with any command you like; the change lands in the file's own buffer as you make it. :w writes every file you touched and u undoes your edits there.

The same works from a list of references or diagnostics.

8. Move through code

If a language server for the file is on your PATH (rust-analyzer, clangd, gopls, pyright and so on), strop starts it. There is nothing to configure.

  • gd goes to the definition; Ctrl-O comes back.
  • grr lists references and grn renames.
  • Space k shows documentation for the thing under the cursor.
  • Space d lists diagnostics; ]d and [d step through them.
  • Completion appears as you type in Insert mode.

If a server did not start, :explain says why.

9. Commit

Changed lines are marked in the gutter; ]c and [c move between them. Space g g opens the status buffer:

  • s stages and u unstages the file under the cursor, or the hunk, or a whole section from its heading.
  • = shows a file's diff under its row.
  • cc opens the commit message in a buffer. :wq commits and :q! aborts. The commit is made by git itself, so your hooks and signing apply.

Space g b switches branch, Space g B shows blame in the gutter, and Space g l opens the log.

10. Run something

Space t opens a shell in a split below. It works like Neovim's terminal: Ctrl-\ Ctrl-N leaves the shell for Normal mode, where the output is a buffer you can search and yank from, and i goes back to typing.

After that

  • strop ssh://devbox/srv/app opens a directory on another machine over SSH; Space o does the same from inside. See Edit over SSH.
  • :theme picks one of six palettes.
  • strop config prints the few settings there are, with their defaults.
  • strop update installs the newest release.
  • The rest is in the docs.
