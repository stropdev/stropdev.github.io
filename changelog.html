Changelog

What changed

The last 3 releases, newest first. Tarballs and checksums are on GitHub releases.

0.63.0 — 2026-11-12

Changed

  • Collecting search hits is one smooth step (plans/0097). Ctrl-O in search results, references or diagnostics now puts the cursor on the hit you had selected, not on the first row. Pressed while the search is still running, it waits and then collects instead of asking you to press it again.
  • ]q / [q step the hits inside the collection, from wherever the cursor is, so you can walk every hit and edit as you go. In any other buffer they still go to the next or previous hit in its file, counted from the hit you were last at. :copen returns to the collection on that hit.
  • Enter in a collection opens the file at the cursor; Ctrl-O comes back.
  • A collection says what it holds: the first row and the buffer name carry the search (search open_picker — 12 hits in 4 files, collection: search open_picker), and each file's card shows its number of hits. Collecting the same search again brings its collection up to date instead of adding another buffer.
  • Plain words in the collection's messages: "hit" throughout, counts written out (1 hit in 1 file), and hit 2 of 4: src/a.rs:11 when stepping.
  • The status line holds still (plans/0098). The keys you are typing (d, d2, "a3d, space g) now sit in a slot of their own and grow to the right, instead of sliding left one cell per key. The line number, column and percentage are fixed-width, so moving from line 9 to 10 no longer shifts everything beside them; the percentage now comes before line:col.
  • A narrow status line shortens before it drops. A long branch name is cut to feature/… before it disappears, and pressing a key takes only the cells that key needs. Before, pressing Space on a full row could drop the whole branch and jump the file name across the screen.
  • Every mode label has room. The mode chip is two cells wider, so PENDING, COMMAND and TERMINAL no longer touch its edge. Groups on the row are always two cells apart, and the row no longer runs into the right edge of the screen.
  • The key card no longer sits on the status line: one empty row parts them. Its +N more line starts under the keys.
  • Inside the : card everything lines up: what you type, the completion names, the substitution summary and the changed lines start in one column, with - and + under the :. A summary too long for the card ends in ….
  • The status line no longer repeats the :s summary that the card already shows; the branch and diagnostics keep their place while you type a substitution.
  • Space s opens at once (plans/0099): the current file's symbols are fetched when you open it and after each finished edit, and kept until the text changes. A second press asks nobody, and the list opens in the same moment as the key. Rows from before an edit are never shown: if the new list is not ready the picker waits for it rather than showing old line numbers.
  • Symbols without a language server: in Rust, Python, C, C++ and Lua files that no server serves — none installed, or still starting — Space s lists the declarations from the syntax tree, and says so. It used to answer only "no language server".

Added

  • REC @a in the status line while a macro records, from qa until q.

Removed

  • g<Space>, ]e / [e and :collection. Enter opens the file, ]q / [q step the hits, and + / - change the context.

Fixed

  • The leader prefix reads space g, not spaceg.
  • Staging always says so. A stage, unstage or discard in the status buffer sometimes finished without its staged a.txt line, when the status refreshed while git was still writing.
  • cc always opens the commit message. When the status buffer refreshed while the message file was opening, the commit message sometimes never appeared.

0.62.0 — 2026-11-11

Changed

  • Git keys mean one thing everywhere: Space g u now unstages the hunk under the cursor (as u does in the status buffer) and Space g X discards it. Space g S is gone. The blame gutter moved from Space g b to Space g B.
  • Git buffers are titled alike: git status, git log, git files, git diff, git hunk.
  • A language server that is not installed says so: lsp: rust-analyzer not found on PATH — rustup component add rust-analyzer instead of "refused". A server that fails to start says it did not start; a project that needs :trust says that.
  • The docs and the in-editor help are rewritten in plain words and checked against the editor: about a hundred corrections, among them five :help rows that described old behaviour. docs/terminal-and-scripting.md is now docs/terminal.md and docs/scripting.md.
  • The README demo shows the everyday loop — find a file, edit, search the project, replace across files, stage and commit — in the default palette.

Added

  • Space g g shows what changed (plans/0096): staged, unstaged and untracked files (and conflicts) in one buffer. s stages, u unstages and - toggles the file under the cursor — or the hunk, or the whole section from its heading. = shows a file's diff under its row, ]c / [c move between hunks, enter opens the file at that line, and X discards after y confirms. The list keeps itself current: after each change, when files change on disk, and when you come back to the window.
  • Space g c commits — cc from the status buffer, ca to amend. The message is written in a buffer that lists what the commit will hold; :wq commits and :q! aborts. The commit is made by git itself, so hooks, signing and your git configuration apply, and a hook's refusal is shown as it wrote it.
  • Space g b switches branch: local and remote branches in the picker, the current one marked. enter switches; the last row creates a branch from the name you typed. If git refuses because your changes would be overwritten, you see its message and nothing changes. Open files follow the new branch.
  • Not yet on SSH projects: status, commit and the branch picker say they need a local repository there. Signs, log, blame and diffs work as before.

Fixed

  • A mistake in config.toml costs only that setting: an unknown theme name, an unknown key or a value strop cannot use is skipped and named in the warning, and every other setting in the file applies. It used to throw away the whole file.
  • The finder and project search no longer list the editor's own lock files (.strop-lock-…) that sit beside open files while hidden files are shown.

0.61.0 — 2026-11-11

Changed

  • Search hits are editable in place. Ctrl-O in search results, references or diagnostics opens a collection; edit inside any excerpt with any command and the change is in the file's buffer in the same keystroke. :w writes every changed file it shows, u undoes what you changed through it (in the files too). Card borders and the "lines omitted" rows are not text and refuse edits. (plans/0094)
  • Quickfix commands. The newest collection is the quickfix list: :copen shows it, ]q / [q (:cnext / :cprev, :cc N) visit its hits, :cdo {cmd} runs an ex command at every hit and :cfdo {cmd} once per file — :cdo s/old/new/ or :cdo norm A;, then :cfdo w. :%s/old/new/g inside a collection substitutes in the excerpts only.
  • Replace across files is two steps. Space R, type, Enter shows the diff; Enter again changes every file and writes it. u in that review puts the buffers and the files back and names any file it could not revert; q cancels.
  • Captures in replace. When the term is a regular expression with groups (regex:, or Alt-R), $1, ${name} and \1 in With expand per hit, in the live -/+ rows and in the result alike.
  • Rename. grn prompts with the current name. A rename in one buffer applies at once; one across several files opens the same review as replace. References move from gr to grr, and gra (actions) and gri (implementation) join them: the four language-server keys of Neovim 0.11.
  • Space a on a file lists code actions only. The filesystem verbs are in the Directory buffer's Space a and under :fs.
  • Filesystem reviews are applied with Enter or :fs apply and cancelled with q or :fs cancel.

Removed

  • :apply-change, :save-change, :undo-change and :cancel-change, the change receipt and the save receipt. The review buffer itself says what was changed and written.
  • Read-only collections. There is one kind, and it is editable.

Fixed

  • The :s preview shows the change. A long line is cut to a window on the changed text, the same window for the removed and the added row; the card no longer covers the statusline.
  • : in a very short terminal no longer panics; with no room for the card, the command line takes the top row.
  • Undoing a replace restores the files, not only the buffers.
  • cc no longer leaves a second cursor on the line, which later edited two places at once.
