roadmap

Where strop is going. Order is priority: editing safety first, new surface area last. The load-bearing detail lives in the repo's plans/ — this page is the public summary.

Shipped

  • 0.6.0 — the input layer: a key-event walker with typed parser state (counts/registers/operators/prefixes); one command table with stable ids drives dispatch, Space ?, and which-key; panes own their selections and scroll; coordinate newtypes guard the Buffer/LSP seams.
  • 0.5.0 — the restructure: generational document ids (the index-alias bug class is dead), one SelectionSet for cursor/visual/multicursor, MotionShape, char-honest grammar args (f é works), an LSP server pool, the leaf command registry, semantic dot-repeat, ActionPlan (preview and execute share one object), and the nvim differential harness in the CI gate.
  • Git as a data model: HEAD → index → worktree → live are four real states; the gutter tints staged lines; verbs name their edge (stage Space g s, unstage Space g S, discard-unstaged Space g u); permalinks pin the surface's commit; visual Space g h is git log -L on the selection.
  • The operator-pending preview: d3w shows the cut before you make it, and preview/execute share one resolver.
  • Multicursor (Q toggle, Space c stack), mirrored edits, one undo unit per cascade.
  • Git surfaces as real buffers: commit browser, file history, blame gutter + card, hunk stage/undo/preview, permalinks — all readonly, yankable, searchable text.
  • LSP: hover, goto-definition, diagnostics gutter + picker, clangd's source↔header switch (gs), layered languages.toml (project over user over embedded).
  • Pickers with streaming rg, file/line previews, and modal input fields (Esc → vim normal mode on the query itself).
  • Global replace (Space R) with row/file exclusion and a full-frame apply preview.
  • The 0.3.9/0.4.0 hardening: unicode-honest word motions, arrow keys everywhere, atomic saves with external-change refusal, readonly enforced at the mutation boundary, honest LSP versions + position encoding.

Next

Ordered by ROI: daily-driver value first, foundations that compound next, far-future last. Within a row, cheaper keys land first.

  • The motion canon — the daily-driver keys, cheapest first: Ctrl-d/u/f/b, zz/zt/zb, H/M/L, {/}, ge/gE, gv, gi, g;/g,, ctrl-^, ZZ; then visual block and :%s + ex ranges. This is what "vim grammar" means when strop is your only editor — and every motion arrives with differential cases against nvim.
  • LSP navigation depth — the reader-first promise: references (gr), implementation, type definition, document symbols, diagnostic traversal (]d/[d). The pool and encoding seams already exist; these are new request types on a proven boundary.
  • The differential gate grows teeth — every fix so far became a corpus case; next is property-generated command streams and register/mark/jumplist comparison. Cheap, and it compounds: every future grammar change is free to land.
  • Tree-sitter text objects — daf, yic, argument/call objects through the same operator resolver and preview. The grammar's object layer exists; these are new resolvers on typed syntax, with lexical fallbacks.
  • Git archaeology depth — symbol history, changed-symbol navigation, branch review as a file sequence. The dive chain + log -L already cover the common case; these are the power layers on top, and they ride SourceLocation.
  • Grapheme clusters (0001 §5.9) — astral-plane and combining-mark text. Real correctness, narrow blast radius; the char-boundary work of 0.3.9 made this an increment, not a rewrite.
  • Measured perf — snapshot-based diff/LSP sync, gutter interval index, real benchmarks (1/10/100MB opens, 100k-line navigation, 1000 cursors) before any rope surgery. No measured pain, no rewrite.
  • A plugin boundary — post-registry-maturity: stable command ids and typed events first; a sandboxed process/WASM edge later. Freezing unstable internals into a public contract is the failure mode.

North star

A reader-first, git-native editor in which every consequential operation is inspectable before it becomes real — vim's grammar, exactly, with git history as a navigable dimension of the document.
