The command line

One binary, subcommands for the occasional jobs, flags for everything else. strop --help prints the same reference live (styled when stdout is a terminal, plain when piped).

Usage: strop [OPTIONS] [FILE[:LINE] | DIR | ssh://URL]

With no subcommand, strop opens the file, directory, or empty buffer — the common case stays strop file.rs.

Commands

CommandWhat it does
strop edit [FILE]open a file, directory, or an empty buffer (the default)
strop remote URLopen an ssh:// file or directory for editing
strop headless SCRIPT [FILE]run the scripted driver over a file
strop replay TRACEreplay a session trace (--script extracts a driver script)
strop export TRACEexport a trace's metadata (privacy-safe, not replayable)
strop configshow the config file and its current values
strop updateself-update (--check only checks)
strop bench [SCENARIO]run the performance-gate scenarios
strop compatdump the vim-compatibility table
strop helpprint help

Options

OptionMeaning
-R, --readonlyopen read-only
+LINEinitial line for FILE (or use FILE:LINE)
--theme NAMEsession-start palette (see Themes)
--remote URLshorthand for strop remote URL
--script PATHheadless driver script (same as headless)
--log[=PATH]record a session trace (STROP_LOG works too)
--log-contentinclude file text in the trace (sensitive)
--log-terminal-contentalso terminal keys and output
-h, --help / -V, --versionhelp and version

Remote locations

ssh://[user@]host[:port]/absolute/path[:LINE]

strop --remote "ssh://tnawara@123.space:4343/etc/app.conf:120" and strop remote ssh://tnawara@123.space:4343/etc/app.conf:120 are the same command. A connected host is editable; -R opens read-only. To read a growing log, pipe it in: ssh devbox tail -f /var/log/app.log | strop -. The full remote contract lives in remote.md.

Exit codes

0 on success, nonzero with a one-line strop: … explanation on stderr otherwise.
